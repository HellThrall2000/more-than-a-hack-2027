# TotalFootball — technical document

More Than A Hack 2027 · FC Barcelona vs Athletic Club · frame-by-frame team possession

Submission file: `TotalFootball.csv` (199,319 rows, `frame,label`), regenerated by `make final NAME=TotalFootball`.

---

## 1. Approach

The output is one label per tactical-video frame: `H` (Barcelona has the ball), `A` (Athletic), `D`
(ball out of play). The ranking metric, spellF1, counts whole possessions, so the system is built to
place few, correct boundaries rather than to be right frame by frame.

The pipeline has two stages.

**Stage 1 — a better ball track ("our ATD").** The provided automatic tracking (ATD) loses the ball
on 41% of graded frames, mostly in gaps longer than 10 s. We search the tactical video for the ball
on every graded frame where the ATD has none, and write a new ATD file in exactly the provided
format: every line, every player value and every original ball value byte-identical, only the
missing ball fields filled. Graded frames with a ball rise from 59.3% to 64.8%.

**Stage 2 — possession from tracking (rule-based, no training).** Applied to our ATD:

| layer | what it does |
|---|---|
| L0 ingest | parse the ATD, map track slots to teams, check alignment with the video and homography |
| L1 players | drop impossible jumps, merge duplicate detections, collective state per frame (team centroids, spread, walking share) |
| L2 ball | clean and smooth the ball; reconstruct gaps as *flight* (fast ball at both ends), *carried* (a player moves with it) or *unknown*; detect touches, control episodes, out-of-play and ball-at-rest |
| L3 features & candidates | per-frame features; restart-formation scores (kick-off, corner, goal kick, throw-in, free kick, penalty); candidate boundaries for turnovers, stoppages and restarts |
| L4 evidence | per-frame log-probabilities for H / A / D from proximity, control, stoppage evidence and a calibrated Smart Tagging prior |
| L5 decoder | semi-Markov Viterbi over each half: segments with log-normal durations, boundaries only at candidates, with posterior sampling |
| L6 output | the segmentation chosen by minimum Bayes risk on spellF1 itself |

Why this design rather than a per-frame classifier: per-frame decisions flicker, and every flicker
is a false possession. A segment decoder with an explicit cost per boundary fixes the count of
possessions first and their edges second, which is what spellF1 rewards.

Why the video stage: almost every possession error traces back to the missing ball. Where the ATD
sees the ball, control alone agrees with the public ground truth on 93–94% of frames; the public
window, which has the ball 88% of the time, scores far better than the rest of the match is likely
to. Recovering the ball improves every downstream layer at once.

## 2. Assets used and dropped

| asset | used? | how |
|---|---|---|
| tactical ATD | **yes** | players and ball; the base of everything |
| tactical homography | **yes** | maps video detections to pitch metres (pixels → normalised pitch) |
| Smart Tagging | **yes** | a soft prior for the team and for set pieces, its weights calibrated per interval against our own control episodes (it is roughly 70% right, so it never decides alone) |
| tactical video | **yes** | ball recovery (stage 1) |
| public 5-minute ground truth | correctness checks only | frame alignment, file format, sanity of labels — never to choose between versions (17 possessions cannot rank them) |
| tactical audio | tried, **dropped** | a referee-whistle detector found 18 events in 2 h 13 min, lining up with tagged set pieces only 1.3× better than chance: the referee is not audible on this track |
| broadcast video and ATD | **not used** | not synchronised with the tactical timeline |
| ROI ball detector trained on the match | tried, **dropped** | searched only near the gap filler's estimate; in long gaps that estimate is ~13 m off, so it recovered 0.02% of frames |
| extra rules: restart team from the taker, goalkeeper catch vs parry, team from player shape (LightGBM on player positions, 82% held-out) | tried, **not in the submission** | each was neutral or lowered the public-window score; the code remains, switched off |
| external data, LLMs, hand labels | not used | — |

### Ball recovery in detail

Tools, filters, data checks and inspection commands are listed in full in
[VIDEO_AND_DATA.md](VIDEO_AND_DATA.md).


- **Detector:** Roboflow's public `football-ball-detection` model (YOLOv8, from
  [github.com/roboflow/sports](https://github.com/roboflow/sports), MIT repository; weights trained
  with Ultralytics, AGPL-3.0). **No fine-tuning, no training on this match.** Weights SHA-256:
  `678fbad05134f19c5094cb8d273812ec9c6691228180d46832551ecf99ed2912`.
- **Inference:** whole 1080p frames at 1280 px, fp16 on an NVIDIA GPU, up to 5 candidates per frame.
- **Filters (no labels involved):**
  1. *on the pitch*: a candidate more than 2 m outside the lines is a spare ball or a ball boy's;
  2. *not static*: an object seen at the same spot (0.5 m grid) on many frames is a painted spot or a
     parked ball;
  3. *steady tracks*: candidates are chained frame to frame only where the jump is one a ball can make
     (40 m/s plus slack); chains shorter than 8 detections are dropped.
- **Self-check (threshold choice, no possession labels):** run on 3,000 frames, in 3 s windows, where
  the ATD does see the ball, and compare. At the chosen confidence 0.5: 45% coverage, 72.9% of
  detections within 2 m of the ATD ball, 85.3% within 5 m.
- **Into our ATD:** only detections at least 1 m inside the lines are written, so a video detection
  can never by itself put the ball out of play. 8,795 frames are filled.

## 3. Possession rules implemented

Full rulebook: [SITUATION.md](SITUATION.md). In short:

- **Dead ball (`D`)** needs positive evidence: the ball out of play (with persistence, because an
  airborne ball projects past the line), a ball at rest while the players walk, both teams slowing
  together, a set-piece or goal tag. **A missing ball is never evidence of `D`.** A collective
  "play has stopped" signal from the players alone (a two-state mixture on team speed, fitted per
  half without labels) covers stoppages where the ball is lost.
- **`D` starts** at the line crossing for a ball going out (extrapolated when the ball is lost on its
  way out), and at the onset of collective deceleration for a whistled stoppage. **`D` ends** when the
  ball leaves rest at a restart, or re-enters over the line at a throw-in.
- **Restart side:** after the ball goes out, the opponent of the last toucher; after a stoppage
  inside the field (usually a foul), the team that had the ball. Kick-offs: read from the player on
  the centre spot, with the halves kicked off by different teams (Law 8).
- **A same-team restart starts a new possession** (`A D A` is two possessions), because the metric
  counts it that way.
- **Possession changes only on control**: the ball within about 1.5 m of a player *and* moving with
  them. Proximity alone is not control, so an opponent shadowing a dribbler, a challenge, a block, an
  aerial duel or a deflection that runs loose does not change the team.
- **Loose balls and passes** stay with the last team in control until the other team controls the ball.
- **The change is timed at the new team's first touch** leading into its control, not at the moment
  control is recognised.

## 4. Results

Public 5-minute window (the only ground truth available; 17 possessions, so differences under about
0.04 spellF1 are noise):

| version | spellF1 | macroF1 |
|---|---|---|
| organiser baseline (`baseline_smooth50`) | 0.326 | 0.621 |
| stage 2 on the provided ATD | 0.497 | 0.777 |
| **stage 2 on our ATD (the submission)** | **0.509** | **0.794** |

The spellF1 gain alone is inside the noise. It is supported by consistency: our ATD raised both
metrics for every rule variant tried (four pairs). The macroF1 gain (+0.017) is above its noise
band, and boundaries moved closer to the truth (mean lag 3.6 frames instead of 13).

Full match (no ground truth, totals only): 296 possessions (mean 11.3 s), 202 dead-ball stretches,
47.3% of graded frames `D`; 58 of the 59 Smart Tagging set pieces fall at one of our dead-ball
stretches.

## 5. Limitations

- **The detector is imperfect:** 73% of its positions land within 2 m of the ATD ball where both
  exist. We set ourselves a 90% bar for trusting it and it does not meet it; it is used because the
  output with it scored better, which on 17 possessions is evidence but not proof.
- **The full match is unvalidated.** On our ATD the pipeline finds 296 possessions instead of 263.
  Part of that is likely real (the ATD often loses the ball at set pieces), part may be false splits.
  Hand-labelled windows inside long ball gaps would settle it; we have none.
- **Boundary timing** is still the largest error on the public window: 15 of 20 true transitions are
  placed more than 1 s away.
- **Goals:** the ball is lost in or behind the goal on all four goals, so the goal-line crossing is
  never observed; the kick-off team comes from who stands on the centre spot.
- **Reproducibility needs a GPU**, and has been verified on one: two full detection runs, in two
  environments, gave identical detections (10,824 of 10,824, none moved by 1 cm). A different GPU or
  driver could in principle shift a borderline detection. A CPU-only run of stage 1 is possible but
  takes many hours.
- **The weights are downloaded** from the public link in Roboflow's own setup script. If it ever
  disappears, any copy with the SHA-256 above works.

With more time: hand-labelled validation windows (above all inside long ball gaps), timing offsets
calibrated on them, and a learned emission model trained on open data from other matches.

## 6. Reproduction

Requirements: Linux, Python 3.12–3.14, [uv](https://docs.astral.sh/uv/), an NVIDIA GPU with CUDA 13
drivers (tested: RTX 4070 SUPER, 12 GB), about 2 GB free disk for caches.

```bash
git clone <this repository> && cd more-than-a-hack-2027
make setup                          # uv sync --extra video  (versions pinned in uv.lock)
# unpack the data bundle into data/tactical/ with its original file names
make test                           # 112 tests on synthetic data, no match data needed
make final NAME=TotalFootball       # -> submissions/TotalFootball.csv, validated
```

`make final` runs, in order (about 25 minutes on the GPU above):

1. `python -m possession.video.fullframe --evaluate` — downloads the detector once into `models/`,
   prints its SHA-256, runs the self-check and stores the threshold;
2. `python -m possession.video.fullframe --force` — detection on every graded frame without an ATD ball;
3. `python -m possession.video.write_atd --out-root cache/atd_ours_inside --inside-m 1.0` — writes
   our ATD and verifies it against the original (players identical, original balls identical, line
   count identical);
4. `python -m possession.run` on our ATD with the version-3 rule settings — the submission;
5. `evaluation/validate_submission.py` on the file.

Everything frame-level that these steps produce (detections, our ATD, caches, submissions) stays in
gitignored folders; the repository contains code only. `make run-all` additionally runs the tests,
the audit, the alternative versions and the public-window scores, and writes a totals-only summary to
`reports/`.

Determinism: fixed seeds and thread counts, stable sorts, rounding of detections to 1 cm and 0.001
confidence; the stage-2 pipeline is pure NumPy on the CPU and byte-for-byte repeatable.
